# Разделение системы на домены

## Принципы разделения (DDD + Data Mesh)

1. **Бизнес-способность** — каждый домен соответствует организационной единице или чёткому бизнес-сценарию.
2. **Независимая эволюция** — домен может менять свои данные и логику без согласования с другими.
3. **Ограниченный контекст (Bounded Context)** — чёткие границы по данным: медицинские карты не пересекаются с финансовыми транзакциями.
4. **Владелец данных (Data Owner)** — у каждого домена есть команда, отвечающая за качество и доступ к своим Data Product'ам.

## Выделенные домены

| Домен | Bounded Context | Владелец | Ключевые данные (внутри домена) | Data Product для других доменов |
|-------|----------------|----------|--------------------------------|--------------------------------|
| **Clinics** | Ведение приёмов, инвентаризация, персонал, расписание | Операционный директор клиник | Записи пациентов (без диагнозов), график врачей, расходники | Слоты занятости, статистика загрузки, метрики по инвентарю |
| **MedicalRecords** | **Закрытый домен** — медицинские карты, диагнозы, снимки, результаты исследований | Главный врач + DPO (безопасность) | Вся охраняемая медтайна | **Только внутрь**: AI-сервисам (по специальному разрешению). **Не идёт в BI портал** |
| **Fintech** | Счета, кредиты, финансовые профили, транзакции | CFO / Руководитель финтех-направления | Балансы, кредитные истории, платежи | Скоринговые агрегаты, финансовые метрики для BI |
| **AIServices** | Модели ИИ, инференс, обучение на медданных | CTO / Head of AI | Обучающие выборки (из MedicalRecords), веса моделей, метрики качества | Метрики диагнозов, confidence scores, рекомендации (без ПДн) |
| **Pharma** (будет через 6-9 мес) | Поставки лекарств, клинические исследования | Директор по фарма-направлению | Остатки препаратов, заказы, протоколы исследований | Прогнозы спроса, агрегаты по клиническим данным |
| **Electronics** (через 12 мес) | Производство и обслуживание медицинского оборудования | Директор по производству | Серийные номера, калибровки, логи ремонтов | Статусы оборудования, предиктивная аналитика |

## Обоснование разделения (связь с бизнес-сценариями)

### Сценарий 1: Вывод нового кредитного продукта (Fintech)
- **Без доменов**: нужно менять DWH, трогать таблицы клиник, согласовывать с ИИ-командой → 2-3 месяца.
- **С доменами**: Fintech-домен развивается независимо. Clinics и MedicalRecords не знают о кредитах. Новый продукт — за 2-3 недели.

### Сценарий 2: Обучение ИИ на медицинских снимках
- **MedicalRecords** предоставляет агрегированные датасеты (с обезличиванием) в **AIServices** через защищённый API.
- Модели обучаются внутри AIServices. Результаты (метрики, диагнозы) не возвращаются в MedicalRecords — только агрегаты для BI.

### Сценарий 3: Интеграция фарма-партнёра
- Новый домен **Pharma** подключается к Data Mesh через API Gateway.
- **Clinics** передаёт статистику по расходу лекарств (агрегаты, без пациентов).
- **Pharma** отдаёт прогнозы поставок.
- **DWH не меняется** — просто регистрируем новый Data Product.

### Сценарий 4: Отчёт для управленца (BI портал)
- BI портал не видит MedicalRecords.
- Запрашивает агрегаты из Fintech (выручка, кредиты), Clinics (загрузка), AIServices (точность диагнозов).
- Каждый домен сам отвечает за свои витрины.

## Преимущества для бизнеса

| Преимущество | Как достигается |
|--------------|----------------|
| **Ускорение time-to-market** | Fintech и Clinics не ждут друг друга. Новый сервис — в своём домене, без согласования с DWH. |
| **Снижение зависимости от DWH** | DWH становится архивом, а не центром. Домены владеют своими данными. |
| **Соблюдение регуляторов** | MedicalRecords изолирован. BI портал физически не может получить медкарты. |
| **Масштабируемость** | Каждый домен масштабируется независимо (разные облачные ресурсы). |
| **Устойчивость** | Отказ Fintech не ломает Clinics. Отказ AI не останавливает кредитование. |
